# Mikage — Asset Lineage Specification

This document defines the lineage and reproducibility requirements for every asset generated by the Mikage Studio OS.

Lineage tracking is mandatory.  
No asset may exist in the system without traceability.

---

## Purpose

The lineage system guarantees that every generated asset can answer:

- where it came from
- what prompt produced it
- which model generated it
- which seed was used
- which references were bound
- which production package created it

And that the asset can be reproduced deterministically.

---

## Core Principle

Every generated asset must preserve:

- production package identity
- prompt pack identity
- model identifier
- seed
- reference inputs
- generation timestamp
- lineage hash

Assets without lineage are invalid.

---

## Required Lineage Fields

Every GeneratedAsset must include:

assetId  
production_package_id  
jobId  

promptPackId  
model  
seed  

referenceInputs  
lineageHash  

generated_at  

These values must remain immutable.

---

## Production Package Binding

Every asset must originate from a ProductionPackage.

ProductionPackage contains:

promptPack  
canonConstraints  
generationObjective  
metadata  

ProductionPackage is the root identity for generation.

---

## Prompt Trace

Every asset must record:

promptPackId  
prompt text  
negative prompts  
prompt version  

Prompt history must never be overwritten.

Prompt revisions must create new promptPack IDs.

---

## Model Trace

Each generation must record the exact model used.

Required fields:

provider  
model  
model version  
adapter  

Example:

provider: gemini  
model: gemini-image-2.0  
adapter: gemini-image-adapter  

---

## Seed Trace

Every generation must record the seed.

seed: number

If the provider generates a seed automatically, it must still be captured.

---

## Reference Trace

If generation uses reference assets, they must be recorded.

Examples:

character reference sheets  
pose references  
style references  
environment references  

Format:

referenceInputs:  
- reference_asset_id  
- reference_asset_id  

---

## Lineage Hash

Each asset must include a lineage hash.

Example calculation source:

hash(
production_package_id +
promptPackId +
model +
seed +
referenceInputs
)

Purpose:

- detect mutation
- verify asset integrity
- reproduce generation

---

## Reproducibility Requirement

The system must be able to recreate an asset if:

prompt pack  
model  
seed  
references  
production package  

are identical.

This is the reproducibility guarantee.

---

## Mutation Rule

Generated assets must never be overwritten.

If an asset changes:

- create a new assetId
- compute a new lineage hash
- reference the previous asset

Example:

derivedFrom: asset_123

---

## Benchmark Integration

The benchmark stage must record lineage metadata.

Benchmark results must include:

assetId  
benchmarkId  
evaluation metrics  
evaluation timestamp  

This preserves traceability between generation and evaluation.

---

## Character Identity Trace (Future)

When the Character Casting Layer exists, generation involving characters must include:

character_reference_id  
face_embedding_id  
style_embedding_id  

This ensures identity reproducibility.

---

## Failure Protection

If lineage metadata cannot be recorded, generation must fail.

Assets missing lineage are invalid.

---

## Architectural Rule

Lineage tracking is a core invariant of Mikage.

Agents must not:

- remove lineage fields
- weaken traceability
- bypass production packages
- create assets outside the pipeline
